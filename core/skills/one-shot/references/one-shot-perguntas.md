# Banco de perguntas one-shot (≥25; adaptar à ideia, cobrir todos os domínios)

Formato: batches de 2-3, recomendada primeiro, default explícito.

**Visão**
1. Qual o problema e para quem? (uma frase)
2. O que é «obra-prima» aqui: 3 critérios de sucesso mensuráveis?
3. O que fica explicitamente fora (não-objetivos)?

**Utilizadores**
4. Quem são os utilizadores e quantos (só o user, equipa, público)?
5. Os 3 fluxos principais, passo a passo?
6. Precisa de contas/autenticação? De que tipo?

**Stack**
7. Linguagem/framework preferidos ou a evitar?
8. Plataforma-alvo (web, desktop, CLI, mobile)?
9. Dependências externas permitidas (APIs, serviços pagos)?

**Dados**
10. Que entidades e relações existem?
11. Onde vivem os dados (ficheiro, SQLite, Postgres, cloud)? Retenção?
12. Há dados pessoais ou sensíveis?

**UX**
13. Estilo visual/referências (links, apps parecidas)?
14. Idioma(s) e acessibilidade (teclado, contraste)?
15. Estados vazios, erro e carregamento: nível de cuidado?

**Segurança**
16. Modelo de ameaças mínimo (quem pode atacar o quê)?
17. Gestão de segredos e configuração por ambiente?

**Testes**
18. Nível de testes exigido (unit, integração, e2e) e cobertura-alvo?
19. Como se prova que funciona como o cliente final (prints, comandos, benchmarks)?

**Deploy**
20. Onde corre (local, VPS, Vercel...)? Há CI?
21. Versionamento e nome do repo em `Documents\code\<projeto>`?

**Prioridades**
22. Núcleo (P1) vs desejável (P2) vs polimento (P3): classificar as funcionalidades.
23. Ordem de entrega preferida e dependências já conhecidas?

**Riscos**
24. Maiores incertezas técnicas e plano B?
25. O que causaria rejeição imediata no fim (inaceitáveis)?

**Horas (sempre última)**
26. Quantas horas de trabalho tens para este projeto até ficar uma obra-prima?
